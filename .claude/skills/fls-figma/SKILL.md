# Верстка з Figma

Макет: $ARGUMENTS

## 1. Отримай дані макета

- **Є посилання Figma і підключений Figma MCP** (інструменти з `figma` у назві): візьми з фрейму структуру, тексти, кольори, шрифти, відступи, розміри та скріншот. Якщо в макеті є змінні/стилі (кольори, типографіка) — забери і їх.
- **Тільки скріншот**: працюй з ним, а точні значення, яких не видно (шрифт, розміри, кольори), спитай одним списком або чесно познач як «на око».
- **Посилання є, а MCP не підключений**: скажи, що його можна підключити (Figma → Dev Mode MCP server), а поки попроси скріншот фрейму і ширину макета.

Визнач ширину макета (зазвичай 1920 / 1440 / 375) і чи є мобільна версія.

## 2. Розбий макет на компоненти

Перед версткою покажи план одним коротким списком:

- які секції → які компоненти (`hero`, `services`, `reviews`...);
- що беремо з готових компонентів збірки (`layout/slider`, `tabs`, `spollers`, `popup`, `forms/*`, `effects/*`) замість написання з нуля;
- повторювані елементи (кнопки, картки, заголовки секцій) — один спільний компонент або глобальний клас.
- якщо багато векторних іконок, роби іконковий шрифт можливостями збірки

Якщо макет великий (3+ секції) — дочекайся «ок» на план.

## 3. Глобальні налаштування (один раз на проєкт)

Звір із макетом і за потреби онови:

- `src/styles/settings.scss` — `$maxWidthContainer`, `$containerPadding`, `$minSize` під макет;
- `src/styles/variables.css` — кольори та шрифти як CSS-змінні (`--main-color`, `--accent`...);
- шрифти — у `src/assets/fonts`.

Перш ніж міняти ці файли, скажи, що саме змінюєш, — вони впливають на весь сайт.

## 4. Верстка кожної секції

Кожну секцію роби за скілом `fls-component` (створення через `npm run add <name> -- --nowp`, BEM, правила з CLAUDE.md). Додатково для макета:

- **Розміри з макета — звичайними `px`** (у `rem` збірка переводить сама); великі значення (заголовки, відступи секцій, gap) — через `@include adaptiveValue("<property>", <desktop>, <mobile>)`, де `<mobile>` береться з мобільного макета, а якщо його немає — розумне значення.
- **Кольори** — тільки через CSS-змінні, без хардкоду hex у компонентах (крім одноразових).
- **Сітки** — CSS Grid / Flex, без абсолютного позиціонування там, де його немає за змістом.
- **Зображення**: експортуй (через MCP) або попроси у `src/assets/img/<section>/`, підключай як `@img/<section>/<file>`; іконки — SVG у `src/assets/svgicons`. Поки картинок немає — тимчасові заглушки з правильними пропорціями.
- **Тексти** — копіюй з макета дослівно.
- **Семантика**: один `h1` на сторінку, далі `h2`/`h3` за ієрархією; кнопка-дія → `<button>`, перехід → `<a>`.

## 5. Звір з макетом

1. Запусти `npm run dev` у фоні й відкрий сторінку в браузері.
2. Зроби скріншот на ширині макета і порівняй із макетом: відступи, розміри шрифтів, кольори, вирівнювання. Виправ розбіжності.
3. Перевір проміжні ширини (1200, 992, 768) і мобільні (375 і мінімальну 320): нічого не вилазить, немає горизонтального скролу.

## 6. Звіт

- які компоненти створено і де вони підключені;
- що змінено в глобальних налаштуваннях;
- що лишилось: відсутні картинки/шрифти, значення «на око», питання щодо поведінки (анімації, ховери, попапи).
