# Передача проєкту клієнту

Проєкт: $ARGUMENTS

## Кроки

1. **Спершу перевірка.** Якщо скіл `fls-launch` у цій сесії ще не запускали — запропонуй пройти його. Передавати сайт із ❌ у критичних пунктах не варто.

2. **Збери дані з проєкту:**
   - сторінки (`src/*.html`, їхні `title`), компоненти в `src/components/custom/`;
   - `template.config.js`: адреса сайту (`seo.url`), SEO, режим WordPress;
   - форми та куди вони надсилають (email через `src/php/sendmail`, Telegram через `src/php/telegram`);
   - підключені сервіси: аналітика, карти (Google Maps), Нова пошта, шрифти Google;
   - для WordPress: тема `fls-theme`, плагіни, блоки ACF у `src/wordpress/fls-theme/components/blocks/`.

3. **Створи документ для клієнта** `HANDOFF.md` у корені проєкту (простою мовою, без технічного жаргону):
   - що це за сайт і з яких сторінок складається;
   - як змінювати вміст: для статичного сайту — що звертатися до розробника або які файли міняти; для WordPress — де в адмінці редагуються сторінки й блоки;
   - куди приходять заявки з форм;
   - які сторонні сервіси підключені та на кого вони зареєстровані (поле «власник акаунта» залиш для заповнення);
   - доступи: **лише перелік** (хостинг, домен, адмінка WordPress, пошта для форм) з порожніми полями — **ніколи не записуй у документ паролі, токени та ключі**;
   - що робити, якщо щось зламалося, і контакти розробника (залиш поле для заповнення).

4. **Фінальна збірка:** `npm run build` (або `npm run wpbuild` для WordPress) без помилок.

5. **Архів.** `npm run zip` пакує `dist` в архів — запусти лише після підтвердження користувача.

6. **Звіт:** де лежить `HANDOFF.md`, що в ньому треба дозаповнити вручну (доступи, власники акаунтів, контакти), чи готовий архів.
