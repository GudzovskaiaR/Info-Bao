# Доступність компонентів FLS

Що перевіряти: $ARGUMENTS

Загальні правила доступності — у розділі «Доступність» файлу `AGENTS.md`. Базові стилі вже є в `src/styles/a11y.scss`.

## Принципи

- **Не ламай наявну розмітку проєктів:** ролі та ARIA-атрибути додавай із JS компонента (якщо їх немає в розмітці), а не вимагай переписати HTML.
- **Нативне краще за ARIA:** `button`, `a`, `details/summary`, `input type="range"`, `select` уже доступні.
- Стан — атрибутами (`aria-expanded`, `aria-selected`, `aria-pressed`, `aria-invalid`), а не лише класами.
- Після закриття попапу, меню чи списку фокус повертається на кнопку, що їх відкрила.
- Анімації JS не запускаються при `isReducedMotion()` з `@js/common/functions.js`.

## Рецепти для готових компонентів

| Компонент | Що потрібно |
|---|---|
| `tabs` | `role="tablist"` на навігації, `role="tab"` + `aria-selected` + `aria-controls` на кнопках, `role="tabpanel"` + `aria-labelledby` на панелях; перемикання стрілками ←/→, Home/End; неактивні таби з `tabindex="-1"` |
| `select` (кастомний) | кнопка-заголовок з `aria-haspopup="listbox"` і `aria-expanded`; список `role="listbox"`, пункти `role="option"` + `aria-selected`; стрілки, Enter, Esc, Home/End; після Esc фокус на заголовок; на touch-пристроях — опція лишати рідний `select` |
| `rating` | унікальне `name` для кожного рейтингу; `aria-label="N з M"` на кожній зірці; видимий фокус; рейтинг лише для показу — `role="img"` + `aria-label`, без полів |
| `quantity` | `aria-label` для «+» і «−» («Збільшити» / «Зменшити»), `aria-label` або `<label>` для поля, `inputmode="numeric"`, оголошення значення через `aria-live="polite"` |
| `slider` (Swiper) | модулі `A11y` і `Keyboard` з українськими підписами (`prevSlideMessage`, `nextSlideMessage`); без автопрокрутки або з кнопкою паузи |
| `showmore` | `aria-expanded` на кнопці; прихований вміст — `inert`, щоб у нього не потрапляв фокус |
| `beforeafter` | керування з клавіатури: `input type="range"` поверх або `role="slider"` + `aria-valuenow` зі стрілками |
| `fullpage` | перемикання стрілками ↑/↓, PageUp/PageDown; при фокусі всередині секції — перехід до неї |
| `marquee` | кнопка паузи; дублікати вмісту з `aria-hidden="true"` |
| `datepicker` | перевір роботу з клавіатури; якщо її немає — на мобільних використовуй `input type="date"` |
| `range` (noUiSlider) | `aria-label` для повзунків через опцію `handleAttributes` |
| `gallery` | змістовні `alt`, а не `alt="Image"` |

## Як перевіряти

1. Прочитай HTML, JS і SCSS компонента.
2. У браузері (`npm run dev`, сторінка компонентів `devcomponents` або сторінка з компонентом):
   - лише клавіатурою: Tab/Shift+Tab, Enter, Space, Esc, стрілки;
   - фокус видно на кожному елементі;
   - стан ARIA змінюється разом із візуальним (перевір через `read_page` чи DevTools);
   - консоль без помилок.
3. Перевір, що зміни не зламали старі проєкти: розмітка без нових атрибутів має працювати так само.

## Звіт

Що було не так (з `файл:рядок`), що змінено, що перевірено в браузері, що лишилось (наприклад, перевірка зі скрінрідером NVDA чи VoiceOver — її робить людина).
