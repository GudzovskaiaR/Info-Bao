# Оновлення проєкту до нової версії збірки

Що оновлюємо: $ARGUMENTS

## 0. Підготовка

- Потрібні два шляхи: **проєкт**, який оновлюємо, і **нова версія збірки** (папка з розпакованою свіжою збіркою). Якщо другого шляху немає — попроси його.
- **Резервна копія:** якщо проєкт у git — переконайся, що всі зміни закомічені, і працюй в окремій гілці (`update-fls`); якщо ні — попроси розробника зробити копію папки. Без резервної копії не продовжуй.

## 1. Що належить проєкту (не перезаписувати)

- `src/components/custom/`, `src/components/pages/`, `src/*.html`;
- `src/assets/`, `src/files/`, `src/php/*/config.php`, налаштовані обробники форм;
- `src/styles/variables.css`, `src/styles/settings.scss`, `src/styles/fonts/`;
- `src/wordpress/fls-theme/components/blocks/` та сторінки теми проєкту;
- значення в `template.config.js`.

## 2. Що належить збірці (оновлювати)

- `template_modules/`, `vite.config.js`, `package.json` (залежності);
- готові компоненти `src/components/layout|forms|effects`, шаблони `src/components/templates/`;
- `src/js/common/`, `src/styles/includes/`, `src/styles/a11y.scss`;
- `.claude/`, `AGENTS.md`, `CLAUDE.md`.

## 3. Порівняння

Для кожного файлу збірки порівняй версію проєкту з новою версією:
- **проєкт не змінював файл** (збігається зі старою збіркою або зміни лише від збірки) — оновлюй;
- **проєкт змінював файл** (наприклад, правки в `layout/header`) — не перезаписуй: покажи різницю і перенеси нові виправлення збірки вручну, зберігши правки проєкту;
- **файл є лише в новій версії** — додай.

Покажи план (список файлів: оновити / злити вручну / додати) і дочекайся підтвердження.

## 4. Відомі зміни, які варто перевірити у старих проєктах

- `template.config.js`: нові блоки (`seo` тощо) — додай із новими значеннями за замовчуванням, наявні значення не чіпай.
- **Поля `locals` сторінок:** якщо шаблон використовує нове поле (`noindex`, `lang`), додай його в усі `src/*.html`, інакше сторінки не зберуться.
- Шаблони `main`/`inner`: посилання «Перейти до вмісту» і `<main id="main" tabindex="-1">` — якщо шаблони змінені в проєкті, перенеси вручну.
- `src/styles/style.scss`: `@use "a11y";` після `@use "variables";`.
- `src/js/app.js`: виклик `addTouchAttr()`.

## 5. Після оновлення

1. `npm install` — лише після підтвердження розробника.
2. `npm run build` — без помилок; SEO-звіт розібраний.
3. `npm run dev` — пройди основні сторінки: меню, попапи, форми, слайдери; адаптив до 320px.
4. Для WordPress — `npm run wpbuild`.

## Звіт

Оновлені файли, злиті вручну (що збережено з проєкту), додані, що лишилось перевірити розробнику.
