# Створення компонента FLS

Аргумент: назва компонента і опис того, що він робить: $ARGUMENTS

## Кроки

1. **Назва.** Латиниця, малі літери, без цифр, пробілів і розділових знаків (`hero`, `pricing`, `reviews`). Якщо користувач дав іншу — запропонуй коректну.

2. **Перевір, чи такого компонента ще немає**, у `src/components/**`. Якщо є схожий готовий (slider, tabs, spollers, popup...) — запропонуй використати його всередині нового, а не писати заново.

3. **Створи заготовку командою збірки** (не вручну):
   ```
   npm run add <name> -- --nowp
   ```
   Без `--nowp` — тільки якщо користувач працює з WordPress.

4. **HTML** (`src/components/custom/<name>/<name>.html`):
   - корінь `<section data-fls-<name> class="<name>">`, всередині `<div class="<name>__container">`;
   - BEM-класи `<name>__element`;
   - змінний вміст передавай через `locals` і виводь як `{{ title }}`, якщо компонент використовуватиметься кілька разів;
   - картинки — `@img/...`.

5. **SCSS** — за правилами з CLAUDE.md: розміри у звичайних `px` (без `toRem()`), `toEm($mobile)` у медіа, `adaptiveValue` для заголовків і відступів, ховер у `html:not([data-fls-touch]) & { }`. Адаптив обов'язковий — до 320px.

6. **JS** — тільки якщо потрібна поведінка. Якщо компонент суто верстка, залиш у `.js` лише `import "./<name>.scss"`. Функцію запускай на `window.addEventListener('load', ...)`, елементи шукай через `[data-fls-<name>]`.

7. **Підключи на сторінку**, якщо користувач назвав, куди: додай
   ```html
   <include src="@components/custom/<name>/<name>.html" locals='{}'></include>
   ```
   у `src/components/pages/<page>/<page>.html`.

8. **Перевір**: запусти `npm run dev` (у фоні), відкрий сторінку в браузері, подивись на десктопі і на ширинах 375 і 320px, перевір консоль на помилки.

9. **Звіт**: які файли створені, як підключити компонент, які `data-`-опції він має.
